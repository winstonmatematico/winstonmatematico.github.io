Seu banco de dados é matemática: relações, funções e o SQL por trás das consultas

Prof. Dr. Winston Aparecido Andrade

Quando você digita uma consulta em um banco de dados, parece que está conversando com um programa. Na verdade, está usando teoria dos conjuntos. Uma tabela é uma relação matemática, uma consulta é uma composição de operações sobre conjuntos, e o SQL é a tradução dessa matemática para um comando que o computador entende. Entender essa base ajuda a escrever consultas melhores e a modelar dados com mais segurança.

O exemplo que vamos usar

Um pequeno banco acadêmico, com três tabelas:

  • ALUNO(ra, nome, curso, semestre): (101, Ana, DSM, 2), (102, Bruno, DSM, 1), (103, Carla, LOG, 2), (104, Diego, DSM, 2).
  • DISCIPLINA(cod, titulo): (MAT019, Matemática para Computação), (PRG001, Programação).
  • MATRICULA(ra, cod, nota): (101, MAT019, 8,5), (102, MAT019, 6,0), (104, MAT019, 4,5), (101, PRG001, 9,0), (103, PRG001, 7,0).

Uma tabela é uma relação

Dados dois conjuntos A e B, o produto cartesiano A × B reúne todos os pares ordenados possíveis, e uma relação é qualquer subconjunto desse produto. Se A tem m elementos e B tem n, o produto tem m · n pares.

Isso explica três características das tabelas: uma linha é uma tupla (um elemento da relação), a tabela não tem linhas repetidas porque conjuntos não repetem elementos, e a ordem das linhas não importa.

Chave primária e função

Repare que ligar o RA ao nome do aluno é uma função: cada RA tem um único nome. Mas o caminho inverso não é: dois alunos diferentes podem se chamar Ana Souza. Por isso o nome não serve para identificar um aluno, e o RA serve. Em linguagem matemática, o RA é injetor: dois alunos diferentes nunca têm o mesmo RA. É exatamente isso que se exige de uma chave primária.

Na tabela MATRICULA, nenhum atributo sozinho identifica uma linha, porque o mesmo RA aparece em várias matrículas. A chave é o par (ra, cod), que é único para cada tupla.

A projeção mostra bem a ligação com os conjuntos. Há três alunos de DSM e um de LOG, mas o resultado de π curso é {DSM, LOG}, porque um conjunto não repete elementos.

Combinando tabelas

Dados de verdade ficam espalhados em várias tabelas, e a junção (⋈) as reúne ligando linhas que têm o mesmo valor em um atributo comum, como o RA. Com ela, dá para encadear operações e responder perguntas completas. Por exemplo: quais alunos tiraram nota abaixo de 5,0?

Em SQL, a mesma consulta é escrita assim:

SELECT DISTINCT a.nome
FROM aluno a
JOIN matricula m ON a.ra = m.ra
WHERE m.nota < 5.0;

A correspondência entre a matemática e o SQL é direta:

  • σ (seleção) corresponde à cláusula WHERE.
  • π (projeção) corresponde à cláusula SELECT.
  • ⋈ (junção) corresponde a JOIN ... ON.
  • ∪, ∩ e − correspondem a UNION, INTERSECT e EXCEPT.

O DISTINCT reproduz a eliminação de repetições dos conjuntos. Sem ele, o SQL, que na prática trabalha com listas que admitem repetição, poderia devolver o mesmo nome mais de uma vez.

Por que isso importa

  • Modelagem: saber que a chave primária é uma função injetora evita tabelas que misturam pessoas diferentes sob o mesmo identificador.
  • Consultas: pensar em operadores encadeados ajuda a quebrar um problema grande em passos simples e a conferir cada um.
  • Otimização: como cada operador devolve uma relação, o banco pode reorganizar a ordem dos passos, por exemplo selecionando antes de juntar, e chegar ao mesmo resultado com muito menos trabalho.

Para fechar

O banco de dados mais moderno do mercado ainda se apoia em ideias de conjuntos, relações e funções que a matemática estudou muito antes de existir computador. Quem domina essa base entende o SQL por dentro, e não só decora comandos. A mesma ideia de que a matemática organiza decisões aparece no artigo sobre lote econômico de compras e no sobre recorrência, juros e Fibonacci.
